### Description

## Purpose

A meteorite `grade_do` batch completed at the agent layer, then failed one job at scored verdict with `_render_score: missing vectors ['Healthcare Domain Expertise']`. The model omitted that rubric code from the encoded line; incompleteness was misclassified as a **technical** fail. That must never happen: missing/extra rubric vectors are **always** a recoverable retry, not a technical failure. The same completeness + retry rule applies to **every** rubric grading path (Do/Get/Like, JD, qualify, prefilter, meteorite twins — all encoded or JSON grade sets scored against a rubric). Separately, operator **Retry** from Skipped must restore a **dispatchable** state for **all** rubric tasks (meteorite or regular) so Scheduled Actions Avail is not stuck at 0 after a hard-coded plain **NEW**.

## Functional scope

1. **Complete grade lines everywhere** — For every consult task that grades against a rubric (standard and meteorite), each response item must include a grade for **every** vector in the rubric used to score that run. Omitting a code is invalid; use `X`/`0` when there is no signal.
2. **Incomplete grades always retry — never technical fail** — When a decoded grade set is missing, extra, or otherwise not a full match to the expected rubric vectors, the job goes to the appropriate **retry holding** state for another LLM attempt. Incomplete grades must **not** transition to `*_FAILED_TECHNICAL_*` / meteorite technical-fail states. Technical fail remains for true infra/apply failures (missing company, prep failure, provider errors, etc.), not for AI omitting a vector.
3. **Prompt / output-contract hardening (all rubric tasks)** — Model-facing instructions and encoded (or JSON) payload contracts for all rubric grading tasks must require the full vector set for that run.
4. **Skipped Retry for all rubric tasks** — Retry from Skipped must not hard-code plain **NEW** for every job. For meteorite and regular pipelines alike, Retry restores the job to the **claimable trigger state for the rubric hop that put it on Skipped** (same state family — meteorite stays meteorite, regular stays regular) so Scheduled Actions Avail becomes **> 0** for the matching dispatch task. Example: a meteorite job that failed at Do re-enters **METEORITE_PASSED_JD** (ready for Do), not plain **NEW**.
5. **Debug visibility (backend)** — With `debug=True` on affected batch paths, each incomplete job logs expected vs decoded vectors under the AST-538 Style D / `|` detail contract.

## Architectural definition

* **Patterns to reuse**
  * `pattern.batch.entity-claim-process-release` — incompleteness is a per-entity process failure inside claim → process → release.
  * `pattern.state.entity-state-transitions` — retry destinations and Skipped Retry targets stay in config/core state policy.
  * `pattern.config.config-block` — Skipped retry target(s), per-task error/retry fields, rubric artifact keys stay config-driven (no hard-coded NEW in UI).
* **New patterns proposed** — none.
* **Applicable statutes**
  * `astral.agent.grade-vector-validation` — enforce full vector set against the live rubric for every graded consult path (not only TASK_CONFIG static `vectors`).
  * `astral.agent.confidence-bounds` — do not invent grades for omitted vectors; model must emit `X`/`0` segments.
  * `astral.patterns.render-verdict-orchestrates-consult` — scored apply stays on the consult verdict path.
  * `astral.state.core-decides-transitions` — retry vs technical-error and Skipped Retry landing policy in core/config.
  * `astral.standards.debug-contract-gated` — missing-vector detail only when debug is on.
  * `universal` product-code set — DRY shared completeness helper across tasks; no one-off Do-only fork.

## Boundaries

* Does **not** change rubric content, importance weights, or `_render_score` math for **complete** grade sets.
* Does **not** treat a true dealbreaker / scored fail (e.g. Remote-First **F**) as incomplete-grade retry — that path already worked in the attached batch.
* Does **not** turn genuine technical failures (prep, missing company, provider) into retry-hold incompleteness.
* Does **not** redesign Skipped UI beyond Retry landing on the correct dispatchable state (and config that drives that).
* Does **not** own later `INVALID_TITLE` re-qualification in the sample `state_history` unless it blocks Retry Avail.
* Does **not** add Betty log-string assertions; Radia enforces debug contract on review.

## Acceptance criteria

1. Replaying any rubric grading batch (Do/Get/Like/JD/qualify/prefilter and meteorite twins) where the model omits at least one expected vector sends that job to **retry holding**, not `*_FAILED_TECHNICAL_*` / meteorite technical-fail.
2. When every rubric vector is present (including intentional `X`/`0`), pass/fail/dealbreaker/scored behavior matches today’s complete-grade behavior.
3. Model-facing contracts for those tasks state that every rubric code must appear; UAT can show a formerly omitting run landing on retry (or completing after a complete response) — never first-touch technical fail for omission.
4. From Skipped, Retry on a **meteorite** job that failed at a rubric hop leaves Avail **> 0** on the matching meteorite dispatch task (not plain **NEW** with Avail 0). Retry on a **regular** job likewise restores that job’s claimable rubric trigger (not a cross-family state).
5. With `debug=True`, incomplete-grade jobs log missing/unexpected vectors under Style D index + `|` detail.
