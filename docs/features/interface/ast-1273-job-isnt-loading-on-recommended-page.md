### Description

## Purpose

A job that already appears on the Recommended page fails when opened: the detail fetch returns HTTP 500 and the modal shows "Job not found," so Susan cannot read the analysis report or act on a job the list already surfaced. This belongs in Interface now because Recommended is the primary review surface — a list row that cannot open blocks the whole review loop for that job.

## Functional scope

* **Detail load for listed Recommended jobs.** Any job shown on the Recommended list must open successfully in the Recommended job report modal via the existing job-detail fetch. A job that lists must not fail the detail path with a server error.
* **Honest failure surfacing.** If the detail fetch fails for a reason other than a true missing job, the modal must not present that failure as "Job not found." True missing jobs may still show not-found; server errors must be distinguishable.
* **Regression guard for the reported case.** The concrete job from the brief (astral job `4a7dbb0c-a1cb-4c1d-ab9d-0c098c8313fc`, company `meteorite-somerset`, state RECOMMENDED with full phase scores / `analysis_upshot`) must open in the modal after the fix on the same environment where the 500 was observed.
* **Backend debug depth (when debug paths are touched).** If the fix touches backend `debug=` surfaces on the detail or agent-story hydration path, `debug=True` must log what was found and what was recorded per step (index headers with universal `index N/M`, primary id, outcome; working detail lines prefixed `|`; long payloads truncated per AST-538 / Code Rules). Backend only.

## Architectural definition

* **Patterns to reuse**
  * `pattern.ui.admin-endpoint` — authenticated thin UI API: `@require_auth`, resolve/load in `src/ui/api/`, React renders the response (jobs detail shares this shape even though it is not under admin).
  * `pattern.layers.import-discipline` — UI API may call core for job load / story hydration; no data-layer imports from UI; no business rules invented only in React.
* **New patterns proposed** — none.
* **Applicable statutes**
  * `astral.idioms.require-auth-on-protected-endpoints` — keep job detail protected.
  * `astral.layers.import-direction` / `astral.layers.ui-config-driven-business-logic` — fix stays in API/core; React does not invent job-existence rules.
  * `astral.standards.in-scope-only` / `astral.standards.no-cross-contamination` / `astral.standards.dry-and-focused-functions` / `astral.standards.public-then-helpers` — universal product-code set.
  * `astral.standards.data-raises-caller-logs` / `astral.standards.logging-via-utils` — data raises; callers log; no ad-hoc logging.
  * `astral.standards.debug-contract-gated` — if any `debug=` path is edited for diagnosis or fix.
  * `astral.batch.entity-agent-responses-latest-only` — detail attaches agent story via latest-per-task refs; do not invent alternate story loading.
  * `astral.ui.frontend-file-placement` / `astral.ui.naming-conventions` — any modal copy/error change stays in existing Interface file layout.

## Boundaries

* Does **not** redesign the Recommended list, report tabs, or artifact generate/cancel flows (AST-858 / AST-948–951 family already shipped).
* Does **not** change consult scoring, dispatch, state transitions, or Meteorite ingest for this job.
* Does **not** broaden into a general jobs-API rewrite — only restore successful detail load (and honest error messaging) for jobs that already list.
* Does **not** require schema migrations or new config keys unless diagnosis proves an existing contract is violated (prefer fix within current contracts).
* Must **not** break In Review / Skipped / other callers of the same job-detail fetch (`JobDetailModal`, artifact editors).

## Acceptance criteria

1. From Recommended, clicking the reported job (or an equivalent RECOMMENDED job that previously 500'd on detail) opens the report modal with job title/company and Summary content — not a not-found empty state.
2. Server log for that open shows the job-detail GET succeeding (not HTTP 500).
3. A deliberate missing job id still surfaces as not-found; a forced non-404 server failure does **not** use the "Job not found" copy.
4. Opening other Recommended rows that already worked before this fix still works (no regression on healthy rows).
5. If backend `debug=` surfaces were touched: with `debug=True`, a failing-then-fixed load path emits per-index found/recorded detail per Code Rules §1.5.1; with `debug=False`, no new debug-contract noise.
