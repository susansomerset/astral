### Description

## As-is

A `craft_company_search_terms` batch (`craft_company_search_terms-11623ae2-…`) stores five `agent_data` rows. SYSTEM, CACHE_A, CACHE_B, and TASK have `entity_id` null (and `entity_type` = candidate). Only RESPONSE has `entity_id` = `somerset`. SYSTEM `ref_agent_data_id` points at an `adhoc-craft_do_rubric-…` row. That split is the shipped AST-984 write rule: RESPONSE gets `entity_id=index`; shared prompt blocks stay untagged and are found later via `batch_id`.

## To-be

Every `agent_data` row in the batch carries the same `entity_id` as the RESPONSE (`somerset` here), not only the RESPONSE row.

## Proposed steps

1. Confirm this is a contract change (stamp `entity_id` on `_store_prompt_blocks` too) vs leaving AST-984 as-is and joining prompt blocks through `batch_id`.
2. If stamping: pass `entity_id=index` into `_store_prompt_blocks` the same way `_store_response_block` already does; check Ad Hoc (`run_adhoc_workbench_test` / AST-1411) uses that path so Test batches match production.
3. If the RESPONSE-only index in `list_entity_latest_agent_refs` / `astral.batch.entity-agent-responses-latest-only` still holds after the stamp, leave the readers; otherwise update them with the statute.
4. Historical backfill of old prompt rows is a separate call — not implied by fixing new writes.
