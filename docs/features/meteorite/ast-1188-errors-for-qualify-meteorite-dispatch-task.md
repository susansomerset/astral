### Description

## Purpose

A live `qualify_meteorite` run claimed 14 **METEORITE_NEW** jobs and finished **COMPLETED with errors** (passed=4, errors=10). Ruth returned JSON `null` for required `job_link` / `job_title` on some rows; schema aborted the whole `do_task` and batch-errored every job in the chunk to **METEORITE_ERROR_QUALIFY**, including siblings with good extracts. Locked product direction: stop whole-batch ERROR on nulls; teach Ruth (via `agent_task`) to synthesize `email-<originalsender>-<timestamp>` links and use email subject as title; park no-subject/no-title rows on **METEORITE_FAILED_QUALIFY**; accept synthesized `email-…` links as QUALIFY (http gate waived for that prefix); replace roster `JD_SCRAPE_FAIL_BOT` with universal **BOT_BLOCKED** for bot/challenge pages (including Cloudflare JD bodies on qualify).

## Functional scope

* Schema accepts null/omit `job_link` and `job_title` on `qualify_meteorite` responses so one weak row cannot abort `do_task` for the chunk.
* When no usable ATS job link exists, Ruth constructs `job_link` as `email-<originalsenderaddress>-<timestamp>` (`qualify_meteorite` `agent_task` instruction). Original sender is discerned by Ruth from the email content sent in assemble — **not** the candidate’s email; no separate forward-parse computation.
* When job title is missing from content, Ruth uses the email **subject** as `job_title` (same `agent_task`).
* When there is no subject and no title in content → **METEORITE_FAILED_QUALIFY** (human-review via existing failed-qualify surface).
* Synthesized `email-…` links are stored as `job_link` and may **METEORITE_QUALIFIED** when JD content is a real job description (http gate waived for that prefix). Ads / unrelated content → Ruth fails → **METEORITE_FAILED_QUALIFY**.
* Sibling jobs in the same chunk with usable fields still **METEORITE_QUALIFIED**; weak rows do not force whole-chunk **METEORITE_ERROR_QUALIFY**.
* True technical failures (unparseable envelope, missing `jobs` list, infra/LLM hard failure) still → **METEORITE_ERROR_QUALIFY**.
* Replace `JD_SCRAPE_FAIL_BOT` with **BOT_BLOCKED** universally for job links that need human attention for bot/challenge blocks; Cloudflare / “Additional Verification Required” / challenge JD bodies on qualify land on **BOT_BLOCKED**, not **METEORITE_QUALIFIED**.
* Assemble sends email message body content to Ruth so she can discern sender/subject/JD; no separate pre-Ruth plumbing child for forwarded-email parsing.
* With `debug=True`, Style D per-job headers + `|` detail record outcome, link source (http ATS vs `email-…`), title source (content vs subject), and bot-block / fail reasons.

## Boundaries

* Does **not** change how jobs enter **METEORITE_NEW** (gazer / Manage Email / Land Meteorite) beyond ensuring assemble content includes the email body Ruth needs.
* Does **not** retarget GDL `evaluate_jd` or rewrite post-qualify meteorite GDL/LIKE states (except any registry rename touch required by **BOT_BLOCKED**).
* Does **not** change roster `qualify_job_listings` behavior except via shared helpers / the universal **BOT_BLOCKED** rename.
* Does **not** treat candidate email as the original sender for synthesized links.
* Does **not** weaken true technical **METEORITE_ERROR_QUALIFY** for unparseable envelopes.
* Does **not** invent a separate meteorite-only bot state — universal **BOT_BLOCKED** replaces `JD_SCRAPE_FAIL_BOT`.

## Acceptance criteria

1. Mixed chunk with some null `job_link`/`job_title` and some full http extracts: good rows **QUALIFY**; others follow synthesize/subject/fail/bot rules; chunk does **not** all-ERROR.
2. No ATS link + usable JD in email content: Ruth returns `email-<originalsender>-<timestamp>`; row can **METEORITE_QUALIFIED** (http gate waived for that prefix).
3. No title in content but subject present: recorded title is the subject; can **QUALIFY** when other gates pass.
4. No title and no subject → **METEORITE_FAILED_QUALIFY** (not QUALIFIED, not whole-batch ERROR).
5. Cloudflare / challenge JD body → **BOT_BLOCKED** (not **METEORITE_QUALIFIED**).
6. `JD_SCRAPE_FAIL_BOT` is gone from config/UI; **BOT_BLOCKED** is the universal bot-block state for jobs that need humans.
7. Genuine unparseable envelope → **METEORITE_ERROR_QUALIFY**.
8. `debug=True` shows per-job Style D headers + detail for link/title source and bot-block/fail reasons.
