### Description

## Purpose

Manage Email **Create** on a multi-job board paste (Dice “Saved jobs” HTML mailed into the Astral inbox) is producing unusable meteorite rows and then failing qualify. Operators need Create → meteorite jobs → `qualify_meteorite` to land real postings with titles and external ids — not SVG/namespace junk and not a blanket `METEORITE_ERROR_QUALIFY`.

## Functional scope

* **List/paste Create hygiene:** When Create runs on an inbox message whose body is a pasted multi-job board (entity-escaped markup and/or Gmail auto-linkified URLs), Astral normalizes that body enough that real job-posting hrefs are discoverable as clean http(s) links, and attribute / asset URLs (e.g. SVG namespace URLs) are not treated as job candidates.
* **Job-link selection and create gates:** Create discovers only URLs that are real job postings. Non-job pages (spec/namespace hosts, company profile/nav chrome, unsubscribe/tracking already excluded) never become meteorite jobs. Existing dedupe (known external id / exact job link) stays. When `debug=True` on the create/ingest path, each candidate link logs found vs recorded/skipped with Style D index headers and `|` detail (AST-538 contract).
* **Qualify after clean Create:** Real Dice (or equivalent ATS) postings created from that path can complete `qualify_meteorite` to **METEORITE_QUALIFIED** with non-empty job title and external `company_job_id`. Usable extracts must not land on **METEORITE_ERROR_QUALIFY** solely because they arrived via Manage Email list Create. True content/bogus failures still use **METEORITE_FAILED_QUALIFY**.

## Acceptance criteria

1. Create on a Dice “Saved jobs” multi-card HTML email (same shape as the Original brief) creates **only** jobs for real job-detail postings present in that list — **zero** jobs whose `job_link` is an SVG/namespace/spec URL (e.g. `w3.org/.../svg`).

> Note: this also needs to work on a simple copy/paste of `\n` delimited job links that the user may have amassed during a heavy day of searching. Do not code for dice exclusively.

1. For each real posting created from that email, `job_link` is the clean ATS job URL (no nested auto-link markup inside the stored link).
2. Re-running Create on the same message skips already-known links/ids without duplicating rows (existing dedupe behavior preserved).

> Be sure that dedupe is keyed by the candidate's companies only.  Do not bounce listings where multiple candidates found the same job.  they can be duplicate across candidates.

1. After Create of only the real postings from that email, running `qualify_meteorite` moves each usable job to **METEORITE_QUALIFIED** with non-empty `job_title` and non-empty `company_job_id`; none of those usable rows end on **METEORITE_ERROR_QUALIFY**.
2. With `debug=True` on Create/ingest, logs show per-link Style D `index N/M` headers and `|` detail for found / skipped / recorded outcomes (not summary-only).
3. A single-link or single-JD Create that already succeeded before this epic still succeeds.
