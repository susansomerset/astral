### Description

## Purpose

`gaze_email` was seeded as a normal `dispatch_task` (correct) but with `auto_mode` true, so the scheduler claimed it on every tick and crashed on Gmail `invalid_scope` — drowning local and Railway logs. Archie’s rule: **never set seed records to Auto = true**. Operators flip AUTO in Task Dispatcher when they want a task live. This epic restores that posture for `gaze_email`, keeps other seed/provision paths honest, and **adds a lasting statute** so future work cannot re-seed Auto=true.

## Functional scope

* **Seed law:** Product seed/provision paths that insert `dispatch_task` rows must seed `auto_mode` **false** (CLICK). Config defaults for those seeds match. Operators may still turn AUTO on later via admin; seeds must not.
* **Statute:** Create and land an approved canon statute stating that seeded/provisioned `dispatch_task` rows are always `auto_mode` false (CLICK). Id to use: `astral.dispatch.seed-auto-false` (or Archie’s rename at plan if catalog placement differs).
* `gaze_email` **fix:** `GAZE_EMAIL_CONFIG` (and any insert of the null-candidate `gaze_email` row) seeds CLICK, not AUTO — correcting the AST-1087/1088 seed that set Auto true.
* **Already-provisioned rows:** If the shared null-candidate `gaze_email` row already exists with AUTO on (local/staging from the bad seed), provision/reconcile brings it back to CLICK so ticks stop without a manual DB edit. Does not forcibly reset rows Susan has intentionally left on AUTO after a conscious admin toggle once the seed law is in place — only correct the bad seed lineage for this shared row (or equivalent idempotent “seed wants CLICK” reconcile).
* Task remains a normal dispatch task: visible in Task Dispatcher, Run works in CLICK, AUTO remains an operator choice after seed.

## Architectural definition

* **Patterns to reuse** — `pattern.config.config-block`: `GAZE_EMAIL_CONFIG.auto_mode` (false) and provision read from config; dispatcher AUTO claim path unchanged.
* **New patterns proposed** — none.
* **Applicable statutes** — `astral.config.config-source-of-truth`; `astral.standards.in-scope-only`; `astral.standards.no-hardcoded-sets` (auto_mode default from config); plus **new** `astral.dispatch.seed-auto-false` (this epic creates it).
* **New statutes proposed** — `astral.dispatch.seed-auto-false`: seeded/provisioned `dispatch_task` rows must have `auto_mode` false; admin may flip AUTO after seed. Archie approved via comment 2026-07-31.

## Boundaries

* Does **not** remove `gaze_email` as a dispatch task or invent a non-dispatch runner.
* Does **not** fix Gmail `invalid_scope` / remint OAuth (AST-1087 UAT / ops) — CLICK seed stops the tick spam; live AUTO success still needs working scopes when Susan enables it.
* Does **not** own Railway stderr→error severity cosmetics, oauth2client `file_cache` noise, or Stytch test UserWarning quieting.
* Does **not** strip admin ability to set AUTO = true on a row after seed.
* Does **not** change Ruth parse, meteorite create, or Manage Email UI.
* Does **not** broaden into rewriting every historical dispatch row in the DB beyond the shared `gaze_email` seed reconcile above.

## Acceptance criteria

1. Fresh provision of the null-candidate `gaze_email` `dispatch_task` row has AUTO off (CLICK).
2. Config seed for that row defaults `auto_mode` false (no seed path writes Auto true for it).
3. On an environment that already has that row stuck AUTO-on from the bad seed, after boot/provision reconcile the row is CLICK and the scheduler does not claim `gaze_email` every tick until Susan turns AUTO on.
4. No other product seed/provision path introduced or left by this epic inserts new `dispatch_task` rows with Auto true.
5. Canon contains active statute `astral.dispatch.seed-auto-false` (or the Archie’s final id) stating seeded dispatch tasks are always auto=false; HARVEST/README updated per statute authoring norms used in-repo.
6. Susan can still flip AUTO on in Task Dispatcher and Run still works in CLICK.
