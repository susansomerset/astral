### Description

## As-is

`@Estelle /check-status <job link>` replies with the no-match text for a job that exists and belongs to the sender. Here that's Somerset's Dice job `6775db61-…`, state `CANDIDATE_SKIPPED`. The link matches `job_link` exactly, and `list_jobs(candidate_id="somerset")` returns the row. Then `_job_owned_by_candidate` in `src/core/tracker.py` drops it. That check decides ownership through `job["company"]` → `company.candidate_id`. Since [AST-1701](https://linear.app/astralcareermatch/issue/AST-1701), the job column is the nullable `company_id`, and meteorite-sourced jobs leave it `NULL` and set `source_entity_id` instead. So the `company` compat alias is `None` and the check returns `False`. [AST-2151](https://linear.app/astralcareermatch/issue/AST-2151) flagged this as an "inherited consequence" and left it out of scope. The same check gates the `get_job_by_pattern` and `get_job_data` contact tasks, so Estelle can't see these jobs through either of those paths.

## To-be

`/check-status`, `get_job_by_pattern`, and `get_job_data` all find any job whose `job.candidate_id` is the sender. `company_id` can be null (meteorite jobs) or set (employer jobs); neither changes the result. Other candidates' jobs stay invisible.

## Proposed steps

1. Change `_job_owned_by_candidate` to decide ownership from `job["candidate_id"] == cid`. That column is already the scoping key `list_jobs` uses (AST-1598). The company-owner lookup goes away, or plan-fix keeps it as a fallback for rows with a blank `candidate_id`, if any exist.
2. Leave the three callers (`/check-status` filter, `get_job_by_pattern` gate, `get_job_data` gate) as they are. They pick up the fix through the shared helper.
3. Re-check against this job: `/check-status https://www.dice.com/job-detail/6889a7c5-d9c5-49e8-9598-ddaf1142df0a` as Somerset returns one match, `CANDIDATE_SKIPPED`.

## Component scope

* `src/core/tracker.py`: modified. `_job_owned_by_candidate` is the one place that rejects company-less jobs, and all three Estelle job reads go through it.

## Technical scope

* `src/core/tracker.py`: modified function `_job_owned_by_candidate`. Ownership comes from the job's own `candidate_id` and no longer depends on the nullable `company_id`. Since AST-1701 that is the only owner field every job row carries. No schema change and no new function.
